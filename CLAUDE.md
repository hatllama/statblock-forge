# Notes for working on this repo

- No build step. `index.html` loads classic scripts that share globals; keep the load order
  (data/party.js → data/srd-monsters.js → js/spell-data.js → js/statblock-parser.js → js/sheet-reader.js → js/forge.js → js/engine/tactical-engine.js → js/war-table.js).
- `js/statblock-parser.js`, `js/spell-data.js` and `js/sheet-reader.js` (character sheets → party members; samples in `tests/sheets/`) must stay DOM-free too (tested under Node). When a statblock parses wrong,
  add it to `tests/statblocks/`, check it with `node tests/parse-dump.js <name>`, and add an expectation in `tests/run.js`.
- `js/engine/tactical-engine.js` must stay DOM-free: it also runs under Node in `tests/run.js`.
- AI knowledge modes (`opts.know = { party, foes }`: open / blind / learn): the AI reads other-side facts only through
  the `k*` accessors (`kHp`, `kMax`, `kDpr`, `kAc`, `kSave`, `kMult`, `kHeals`, `kAreas`, `kAreasNext`, `kReach`, `kCaster`, `kLegRes`, `kImmune`, `kBossHp`, `leftFor`). New AI
  code that looks at an enemy's hp, AC, saves, resistances, actions or the day's length should go through them too;
  dice and rules keep using the real numbers. `leftFor` (fights still to come): open and learn read the real count,
  blind assumes `BLIND_FIGHTS`; `opts.expectFights` (War Table "Fights the party expects today") overrides learn and blind.
- After changing engine rules or AI, run `npm test` (checks wall/LoS violations, actors that are dead,
  hidden in plain sight, odds sanity) and play a fight on the War Table to eyeball the replay.
- npm scripts: `test`, `compare` (tests/ai-compare.js), `flagoff` (tests/flagoff-hash.js), `build-party`, `build-srd`, `build-threat`, `serve` (tools/serve.js, static server on http://localhost:8080).
- Exports follow the day save-file format checked by `checkRealSchema` and `validateMonster` in `js/forge.js`;
  keep those checks in step with any format change.
- Creature/action extras live under `ext`; plain exports ignore them. Anything War-Table-only that would
  confuse the export gets `ext.wtOnly`; export-only stand-ins get `ext.wtSkip`.
- The built-in party and the class roster (`CLASS_BUILDS`, one level-5 build per class) are generated: edit
  `tools/build-party.js`, run `node tools/build-party.js` (rewrites `data/party.js`), then bump `PARTY_VERSION` in
  `js/forge.js` and list changed ids in `PARTY_UPDATES` so saved workspaces update. Zaki's own party lives in
  `parties/zaki-party-level-5.json` (load it with Day file → Load just the party).
- The official monsters in the Library (`data/srd-monsters.js`, `SRD_MONSTERS`) are generated from SRD 5.2 data by
  `tools/build-srd.js` (see its header for the 5e-database clone). Only SRD 5.2 monsters, never other books; keep the
  CC-BY attribution (`SRD_ATTRIBUTION`, the footer) wherever they appear. They are parsed by the statblock reader when
  added, so parser changes apply to them; `tests/run.js` checks they all parse and fight.
- Browser support: keep to syntax older Safari/iOS can run — no regex lookbehind (`(?<=` / `(?<!`), no `??=`/`||=`, no `structuredClone`.
  One unsupported regex makes the whole script fail to load.
- Every release: bump the `?v=` on the script/style tags in `index.html` so visitors don't keep a cached old copy.
- The Forge UI is one sidebar (`#forgeSide`) and one main panel (`#forgeDynamic`, plus the static `#panelImport` and `#panelFile`).
  What shows is `sel` in `js/forge.js`; every editor listens on `#forgeDynamic`. Creature keys: `'p3'` = party member 3,
  `'2'` = monster 2 of `encounters[activeIdx]`. The War Table calls `renderParty`/`renderMonsters`/`renderPartyBar`; keep those names.

## Where things live
Files are huge: `grep -n "function name"` (or `Sim.prototype.name`) and read just that range, never the whole file. Names are anchors, not line numbers.
- `tactical-engine.js` rules: `Sim.prototype.usable`/`spend` (uses, pools, recharge), `saveRoll`/`saveBonusFor`, `attackRoll`, `damage`, `moveAlong`, `settleAltitude` (flyers), `doAction` (resolves one action).
- `tactical-engine.js` pre-fight buffs: `runDay` calls `morningCasts` (party only, `opts.prefightBuffs`, default on; War Table setting "Pre-fight buffs" is the one switch) so long, non-concentration buffs are cast once before fight 1, spending real slots. `PREFIGHT_SPELLS` is the table (Aid, Mage Armor, Death Ward: min level, `ok`, `gain`, `apply`); `PREFIGHT` holds the weights incl. `share` (`opts.morningShare`). A spell joins with `ext.prefight` (inert in a fight) and a table entry. `ext` keys: `prefight` (spell kind), `unarmored` + `dexMod` (creature: wears no armor; Mage Armor target), unit fields `dayBuffs`, `deathWard`, `aided`. Design in `docs/ai-v2.md`. Flag-off hashes: run `PREFIGHT=0 node tests/flagoff-hash.js` to compare with logs from before it existed.
- `tactical-engine.js` footprints: a unit's `x,y` is the top-left square of its body and `u.n` its side (`FOOT`: Large 2, Huge 3, Gargantuan 4, smaller 1). Use `dist`/`distXY`/`gapTo` (gaps between bodies, `distXY` measures from the acting unit's `_mn`), `occupant(x,y,n,skip)`/`fits`/`takenFor` (who is in the way, where a body can stand), `coversIn` (zones) and the reach maps (a big mover needs its whole body clear); never compare raw `.x`/`.y` between units. Line of sight between bodies is `losB`/`losU` (any square to any square; `los` is square to square), cover the least over a body's squares; a cone, line or adjacent cube from a big creature starts on its body's edge (`bodyEdge`, `areaOnBody`, `aimStraight`/`aimCubeFrom`), an emanation from its body (`spec.bn`). A hostile creature's space can be passed if Tiny or two sizes apart. Audit of what is and isn't real: "Size as a real rule" in `docs/ai-v2.md`.
- `tactical-engine.js` area spacing (v2): `v2Danger`'s `spacing` prices each enemy area attack `kAreasNext` reports (chance ready next turn × damage to one caught × what the square adds to our creatures caught, (2 (M1 − 1) + 1) / N), weighed × `safety` × `w.areaRisk`; the old AI keeps `spacingAt`/`kAreas`.
- `tactical-engine.js` areas: `areaSpec` → `areaCells` → `inArea` (top of file, plus `TEMPLATES`).
- `tactical-engine.js` lingering spells: a spell with `ext.zone.dmg` (Spirit Guardians, Moonbeam, Wall of Fire…) leaves a zone that hurts on `zoneTick` (start of a creature's turn) and `zoneEnter` (after a move), once a round each, via `zoneHit` → `resolveAttackAction`; `ext.zone.follow` moves it with the caster, `ext.hold` is its length in rounds (`expireZones`), `ext.sustain` (Moonbeam, Call Lightning, Sunbeam) lets the caster re-use it free (`sustaining`). Flag a new one in `spell-data.js`, then rebuild the party.
- `tactical-engine.js` turn flow: `turn` → `tacticalTurnInner` (movement + action plan) → `choose` (pick an action per slot) → `plan`/`planInner` (target + position scoring); `surge` is the action-surge style extra action; `runDay` is the whole-day loop.
- `tactical-engine.js` AI v2 (`opts.ai = 'v2'` or `{ party: 'v2' }`; non-casters and full casters, `casterKind` decides — half/third casters stay v1; design in `docs/ai-v2.md`): the "AI v2" block — `AI_BASE`/`AI_PROFILES` (every weight and threshold; `ext.aiProfile` picks one), `v2Setup`/`v2Eligible` (who uses it, per fight), `v2Posture`, `v2Value`/`v2SelfValue`/`v2AllyValue`/`v2Control` (what an option is worth), `v2Holding` (running concentration), `v2FF` (friendly fire), `v2TurnInner` (squares × options incl. each spell at each slot level via `v2CastLevels`/`castCopy`, and the Misty Step `jump` mode), `v2Aim`/`v2AimValue`/`v2Act` (re-aim after moving), `v2Bonus`, `v2Reckless`, `v2Surge`, `v2Pace` (pacing; spell slots as one pool of slot levels, `v2Recovery`), `v2ReactOk`, `v2Words` (intent lines), `v2Burn`/`v2BurnPlan` (Legendary Resistance: burn it with cheap control or race the boss's HP; `AI_BASE.burn`, `controller` leans burn, `artillery` race; `burn.bias` 0 = off; a burner's effect is lifted in `v2TurnInner`, the monster spends LR in `saveRoll` only on disabling/high-damage effects). `kLegRes` is the party's count: real in open; blind/learn none until a use is seen, then 3 less the uses seen. The plan runs where `burn.modes` says (open only); control into LR is `w.legRes` / uses left. `w.buffRounds` caps how far ahead a buff is counted. The slot level v2 picks reaches `spend` through `u.castAt`. `turn` branches on `u.v2`; with the flag off the old AI plays exactly as before (check: `node tests/flagoff-hash.js` before and after a change, the output must match). New v2 behaviour = a weight in `AI_BASE` + a term, not a veto. Compare with `node tests/ai-compare.js [runs] [filter]` (old vs v2 tables, not part of `npm test`).
- `tactical-engine.js` monster tiers (phase 4; `docs/ai-v2.md` "Monster intelligence tiers"): `opts.ai.foes = 'tiers'` puts every monster on v2 with `AI_TIERS.profiles[tier]` (`tierOf`/`tierProfile`, `ext.aiTier` overrides, Int/Wis from `ext.scores`, which the day export strips); a profile's `know: 'blind'` is read through `kModeFor`, its `morale` by `moraleBreaks`. `foes: 'v2'` keeps the old gate and one profile. Harness: `node tests/ai-compare.js 200 '^TIER'` (`TIER_MODES=blind`, `MORALE=on`).
- `tactical-engine.js` boss tier (phase 4b; `docs/ai-v2.md` "Boss tier"): `tierOf` gives `boss` to legendary/lair/Legendary Resistance/foe-acting reactions; `AI_BASE.boss` (neutral in the base) holds its knobs, `AI_TIERS.profiles.boss` sets them. `bossShare` (`solo`: self-care when alone, in `v2TurnInner`), `bossLegendary`/`bossOptions`/`bossBefore` (legendary actions: which and when; `legendary()` calls it), `bossLair` (`lair()`), `bossLR`/`bossEffect` (`saveRoll`, via `this._saveA`), `bossRecharge` (main-turn recharge price), `bossPlan`/`bossPlanTarget` (`ext.aiPlan`, stripped by `exportCreature`), `kDprOpen`/`dprSeenBy`/`kDprW` (open mode reads a caster's spells, not just its first attack: `w.dprSeenPC` 1 for the party, `w.dprSeen` for monsters (boss only), `dprSeenDealt`, `dprSeenGap`). Harness: `node tests/ai-compare.js 200 '^BOSS'`.
- `tactical-engine.js` reactions (step 3b; `docs/ai-v2.md` "Reactions as a layer"): `reactKind`/`REACT_ON` say what an action-slot-4 reaction is and what triggers it (`ext.react` carries the limit flags `roll`, `types`, `on`), `reactFind`/`reactTake`/`reactPrice` find, spend and price one (`AI_BASE.react` holds the weights). Triggers: `attackRoll` → `reactHitOld` (v1 thresholds, unchanged) / `reactHitV2` (Shield, Silvery Barbs, Lucky), `saveRoll` → `reactSaveV2` (Barbs on a foe's save), `damage` → `v2ReactOk` → `reactCutNow` (Uncanny Dodge, Deflect Attacks go to the hit that matters), `doAction` → `counterCheck` (Counterspell; a spell is `a._spell` or `a.ext.innateSpell`), `moveAlongSteps` → `readyStrike` (a readied attack; the `ready` option sits beside Dodge in `v2TurnInner`).
- `tactical-engine.js` downed and dead allies (step 2.12; `docs/ai-v2.md`): `v2BackUp`/`deathOdds` (a heal on an ally at 0 HP; `w.back*`), `revivable`/`reviveDuty`/`v2Reserve`/`v2KeepCost` (a death keeps a slot; `pacing.revive*`), `endFightRevives`/`wakeReviver` (cast when a won fight ends). `ext.revivify` is never a turn option; v2 only, so v1 logs do not change. Harness: `DOWNED=1 node tests/ai-compare.js [runs]`, `node tests/ai-compare.js 200 '^D[0-9]'`, `'^R[0-9]'`.
- `tactical-engine.js` knowledge: `kMax`, `kHp`, `kDpr`, `kAc`, `kSave`, `kMult`, `kHeals`, `kAreas`, `kAreasNext` (v2: with the chance each is ready next turn), `kReach`, `kCaster`, `kLegRes`, `kImmune`, `kBossHp`, `leftFor`, `learnSave` (the "WHAT EACH SIDE KNOWS" block). Learn on v2 is `keen`: `seeBloodied`/`learnBounds` read the bloodied flag and `netLost` (`opts.threat: false` for the classic reading). It also uses `threat` (the party's strength score per kind; prior `threatPrior`, table `AI_BASE.threat`, generated by `node tools/build-threat.js`) in place of the size guess; `opts.threat: 'bounds'` is the bloodied reading alone, `false` the classic reading. Design and results in `docs/ai-v2.md` ("The threat estimate"). v2 learn's log baseline is `tests/fixtures/hashes-v2-learn.txt` (`AI=v2 KNOW=learn node tests/flagoff-hash.js`).
- `forge.js` validation/format: `validateMonster`, `checkRealSchema`, `buildDayObject` (export), `exportCreature`, `applyWorkspace`/`loadWorkspace`.
- `forge.js` UI: `renderSide` (sidebar), `sheetHtml` (creature sheet), `actionEditor` + `freqFields` (action editor), `handleFieldChange` (all field edits), `resourcesPanel`/`onResourceField` (pools).
- `forge.js` imports: `onSheetFile` → `readSheet` (character sheets; `readSheetWithClaude` for the PDF/AI path); `forgeOne` (Claude API statblock converter).
- `statblock-parser.js`: `parseOne` (one block → creature; the `rank` const inside it orders actions), `readMultiattack`/`comboAction`, `readSaveEffect`, `areaInfo`.
- `sheet-reader.js`: `fromDDB`/`fromFoundry`/`fromText` → facts → `build`; `classFeatures` adds per-class actions; `CUSTOM` holds spells the spell data lacks.
- `sheet-reader.js` PDFs: `forge.js` `pdfText` hands the page text items to `SheetReader.layoutText`, which joins them into rows by their gaps and puts "Label: value" lines (value above or beside its caption, as on Roll20 sheets) in front; `fromText` reads those like any "Name: value" line. `tests/sheets/niko-roll20.txt` and `tacitus-roll20.txt` are that output (made with pdf.js 3.11.174 from the PDFs, which are not committed).
- `war-table.js`: `simOptsFor` (sim settings per encounter), `renderSetup`, `renderInspect`, odds (`runOdds`/`renderOdds`/`drawHist`), replay (`startReplay`/`showFrame`/`play`/`animateEvent`).
- `tests/run.js` is one script of `section('…')` blocks (the rule checks per AI incl. v2, area templates, terrain, flying, parser, class roster, knowledge modes, SRD monsters, character sheets, AI v2). Fixtures: `tests/statblocks`, `tests/sheets`, `tests/fixtures` (day files).

How to:
- Add a spell the spell data lacks: add an entry to `CUSTOM` in `sheet-reader.js` (same action shape as `misty step`); `build` uses it when `SD` has no entry.
- Pooled resource: the creature declares pools in `ext.resources`; an action draws on one via `ext.resource` (pool name) and `ext.resourceCost` (default 1). The engine checks/spends it in `usable`/`spend` (`u.uses` key `res:<name>`); the Forge edits it in `resourcesPanel`.
- Add a class feature to the sheet reader: add an `if (classLevel) { add({...}); ext.x = … }` branch in `classFeatures` (use `lv`/`sub`), then add a sample under `tests/sheets` and an expectation in the "Character sheets" section of `tests/run.js`.

## AI worker rules
Plan and phases: `docs/ai-roadmap.md`; what exists: `docs/ai-v2.md`. The rules engine is not AI; AI work does not change it.
1. One currency: every option reduces to expected value in the same unit; a new term states what it measures.
2. Terms, not vetoes: add a weighted term, never a special-case rule.
3. Estimates, not lookahead: no rollouts or search.
4. Other-side facts only through the `k*` accessors; dice and rules use real numbers.
5. Weights and thresholds are plain data in `AI_PROFILES`/`AI_BASE`; no hardcoded numbers outside it.
6. Calibrate by outcome: a behavior change needs a harness scenario with win rate ±SE (200+ runs, same seeds); nothing may get worse beyond noise.
7. Flag-off logs stay identical (`node tests/flagoff-hash.js`) until the default switch.
8. Update `docs/ai-v2.md` BEFORE writing code; keep `npm test` green; bump `?v=` on changed script tags; engine DOM-free; Safari-safe syntax; commit with attribution lines.
